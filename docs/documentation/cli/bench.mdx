## Usage

```bash
wasmdee bench <wasm-path-or-http-url> [flags]
```

## Description

Measures function invocation latency with cold, rehydrate, and warm phases for local Wasm modules, or warm-only HTTP latency for remote endpoints. Produces histogram statistics for apples-to-apples comparisons between wasmdee and container-based platforms.

## Modes

| Target | Mode | What's Measured |
|---|---|---|
| `./hello.wasm` | `wasmdee-local` | Cold start, rehydrate, warm dispatch |
| `http://...` | `http` | Warm HTTP round-trip only |

## Flags

| Flag | Default | Description |
|---|---|---|
| `--name` | filename | Function name for local benchmarks |
| `--label` | mode | Human label for the report (e.g., "openfaas") |
| `--data` / `-d` | `""` | Request body or stdin payload |
| `--arg` | | Argv arguments for local Wasm (repeatable) |
| `--iterations` | `100` | Measured warm invocations |
| `--cold-runs` | `5` | Fresh-engine cold runs |
| `--warmup` | `10` | Warmup invocations excluded from results |
| `--concurrency` | `1` | Parallel measured invocations |
| `--timeout` | `5s` | Per-invocation timeout |
| `--min-workers` | `1` | Minimum dispatcher workers |
| `--max-workers` | `NumCPU * 4` | Maximum dispatcher workers |
| `--scale-down-after` | `5s` | Idle worker retirement for benchmark |
| `--scale-to-zero-after` | `0` | Module eviction (0 = disabled) |
| `--json` | `false` | Machine-readable JSON output |

## Examples

```bash
# Benchmark a local Wasm module
wasmdee bench ./hello.wasm --iterations 1000 --warmup 100 --concurrency 8

# JSON output for CI/scripting
wasmdee bench ./hello.wasm --iterations 500 --json > results.json

# Compare wasmdee HTTP gateway vs OpenFaaS
wasmdee bench http://127.0.0.1:8080/invoke/hello --label wasmdee-http
wasmdee bench http://127.0.0.1:8081/function/hello --label openfaas
```

## Measurement Phases

### Cold
A fresh Wazero engine and empty compilation cache for each run. Measures the worst-case first-invocation latency including full compilation.

### Rehydrate
Evicts the compiled module from the in-process warm pool but preserves the file-backed compilation cache. Measures reload cost when a function was scaled to zero.

### Warm
Uses the long-lived engine with the compiled module already in memory. Measures the dispatcher + instantiation + execution path — this is the steady-state latency.

## Notes

- Cold and rehydrate phases are only measured for local Wasm targets
- HTTP mode is intentionally simple: it does a POST and measures round-trip time
- Use `--json` output for automated comparison scripts
- See [Benchmarking Guide](/guides/benchmarking) before publishing performance claims
